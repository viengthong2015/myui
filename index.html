1. ບັນຫາທີ່ພົບ ຫຼື ສີ່ທ້າທາຍ (The Challenges)

1 Hard-coded strings: ຄຳສັບ (label) ຖືກກຳນົດຕາຍຕົວໃນ Code.
2 ຄວາມຊ້ຳຊ້ອນ: ຄຳສັບດຽວກັນຖືກກຳນົດໄວ້ຫຼາຍບ່ອນໃນ Backend.
3 ຄວາມບໍ່ສອດຄ່ອງ: ຂາດມາດຕະຖານການແປ (Technical Terms) ພາຍໃນທີມ.
4 ການປັບປ່ຽນ: ຕ້ອງແມ່ນນັກພັດທະນາທຸກຄັ້ງ ເມື່ອມີການປັບປ່ຽນ ຫຼື ປ່ຽນແປງພາສາໃນ UI.
5 ການ Build ລະບົບຄືນ: ທຸກຄັ້ງທີ່ແປໃໝ່ ຫຼືປ່ຽນແປງ ຄຳສັບ ຕ້ອງ Deploy ລະບົບໃໝ່.

2. ຈຸດປະສົງຂອງໂຄງການ (Objectives)

1 ອອກແບບ Model ທີ່ຮອງຮັບຄຳສັບຂອງ UI ພ້ອມທາງການແປເປັນຫຼາຍໆພາສາ
2 ພັດທະນາ Translation Engine ທີ່ເຮັດວຽກແບບ Runtime
3 ສ້າງ Admin Interface ໃຫ້ຜູ້ໃຊ້ທົ່ວໄປສາມາດເພີ່ມພາສາທີ່ຕົນເອງຕ້ອງການ ແລະ ສາມາດແປ ແລະ ແກ້ໄຂ ໂດຍບໍ່ຕ້ອງ redeploy ຫຼື rebuild
4 ປະເມີນປະສິດທິພາບປຽບທຽບກັບວິທີການແບບດັ້ງເດີມ

3. ໂຄງສ້າງລະບົບ (System Architecture)

1 ຖານຂໍ້ມູນ: ເກັບຄຳສັບ (Key) ແລະ ຄຳແປ (Value).
2 ການເຊື່ອມຕໍ່: ຮັບຄຳແປຜ່ານ API ຫຼື/ແລະ Server-Client (java RMI).
3 ເຄື່ອງມືການແປ: ສະແດງ ຄຳສັບໃສ່ UI ແບບ Dynamic (Runtime).
4 Admin Interface: ໃຫ້ຜູ້ບໍລິຫານລະບົບສາມາດເພີ່ມ, ແກ້ໄຂ ແລະ ຈັດການຄຳແປພາສາໄດ້ດ້ວຍຕົນເອງ

4. ການອອກແບບຖານຂໍ້ມູນ (Database) ແລະ ເຕັກໂນໂລຊີ (Technologies)

1 ທຸກຄຳສັບ (label) ຕ້ອງຈັດເກັບແບບ Single Source of Truth ແລະ ຕ້ອງ unique
2 ຮອງຮັບການ Reuse ຄຳສັບດຽວກັນໃນທຸກ Module
3 ເກັບຂໍ້ມູນ: Language (ID, Code, Font), UI_Keys, Translations (Value), ...
4 Technologies: [Java-RMI, Java-Swing], [Python/Node.js ແລະ Django/react framework], ...
5 ຮູບແບບ Application: Windows Application, Web Application & mobile application, ...

5. ຜົນປະໂຫຍດ ແລະ ການປະເມີນ

1 ຄວາມຢືດຢຸ່ນສູງ (High Agility) ໃນການປັບປ່ຽນ ພາສາໃນ UI
2 ປະຢັດເວລາໃນການແປ, ການພັດພັດທະນາ ແລະ ຫຼຸດຜ່ອນຄ່າໃຊ້ຈ່າຍ
3 ສະດວກຕໍ່ຜູ້ໃຊ້
4 ຜູ້ໃຊ້ສາມາດຈັດການ ການແປດ້ວຍຕົນເອງ ໂດຍບໍ່ຕ້ອງການການ build app ຄືນໃໝ່

6. ສາທິດລະບົບ (Demontration) - ຮູບແບບ Windown base
